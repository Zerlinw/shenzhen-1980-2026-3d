# Contributing

Thanks for taking a look. This is a dependency-free, single-page WebGL project;
the shipped artifact is a generated `index.html`, while all authoring happens in
`src/`.

## Requirements

- **Node.js 22+** for the build and screenshot scripts (`fetch` + global `WebSocket`).
- A modern Chromium-based browser for optional headless screenshots.
- No `npm install` is required: the project has no npm dependencies.

## Local workflow

```bash
npm run serve     # http://127.0.0.1:8123/index.html
npm run build     # regenerate index.html from src/ + vendor/
npm run check     # syntax check + build
```

**Never edit `index.html` by hand.** It is generated by `scripts/build.mjs` from:

- `src/shell.html` — page skeleton and HUD markup
- `src/style.css` — HUD, timeline and night-mode styling
- `src/app.js` — Three.js day/night scenes, figures, timeline, post-processing
- `vendor/three.min.js` — vendored Three.js r160

Edit the source, run `npm run build`, and commit both the source and the rebuilt
`index.html`. CI verifies that the committed build matches the source.

## Optional visual checks

```bash
npm run smoke
npm run shoot -- --years=2026 --close --night
```

The scripts auto-detect Chrome/Edge/Chromium. If discovery fails:

```bash
CHROME=/absolute/path/to/chrome npm run shoot -- --years=2026 --night
```

Screenshots are written to `docs/screenshots/`. The smoke test writes
`smoke-900.png` and `smoke-night-900.png`.

## Design constraints

Please keep these invariants when changing the piece:

1. **Day and night are separate scenes.** The day scene owns the paper/resin
   diorama, the 1980—2026 timeline, the 20 figures and the three everyday
   scenes. The night scene is a separate `nightScene`/camera/post pipeline.
   Switching must preserve the day year, playback state and orbit.
2. **The day model remains handcrafted**, not a night render with a filter:
   single soft key light, matte materials, no Bloom/no neon window noise, no
   full-frame damaged-texture overlays.
3. **The night scene is fixed at 2026** and is allowed to be a poster-like
   composition: neon windows, drones and fireworks. Do not make it a second
   timeline unless the UX is redesigned.
4. **No external runtime assets.** Textures, signs, steam, water, drones and
   fireworks must stay procedural. No CDN, no font download, no image files at
   runtime.
5. **Keep the micro-scale readable.** 20 unique 1:87 figures, feet on the
   ground, hands touching props, no recognizable faces.
6. **Performance budget:** ~150 draw calls / <80k triangles for the day view;
   prefer merged geometry and `Points` for the night effects.
7. **Accessibility:** preserve keyboard controls (`Space`, `←/→`, `R`, `N`,
   `Esc`), button labels and reduced-motion CSS.

## Pull requests

- Keep commits focused; a visual change should include updated screenshots.
- Run `npm run check` and `npm run smoke` before opening a PR.
- Describe **what changed visually**, not only which functions were touched.
- If you change the build or file layout, update `README.md`,
  `docs/ARCHITECTURE.md` and `.github/workflows/` together.
- Do not commit browser profiles, `.cache/`, `node_modules/` or local sandbox
  artifacts; they are ignored by `.gitignore`.
